# One2All 登录态持久化设计

## 背景

One2All 当前提单流程依赖 Codex 右侧浏览器的临时控制会话。会话重连后无法稳定复用已登录状态，备用自动化浏览器又会启动全新的临时 Profile，导致反复回到登录页，阻塞带截图的 BUG 提交。

## 目标

- 为 One2All 建立独立、可复用的本地浏览器 Profile。
- 首次登录后，后续唤醒自动复用该 Profile，不再默认创建临时会话。
- 登录态只服务于 `http://192.168.113.115:32633`，不与其他站点共享。
- 保留可见浏览器操作和现有 One2All 字段、附件、保存后验证规则。

## 非目标

- 不读取、导出或打印密码、Cookie、Token、本地存储内容。
- 不改变 One2All 的需求匹配、严重级别、优先级或 BUG 字段规则。
- 不影响 Zentao 或其他测试站点的浏览器配置。

## 方案

采用专属 Profile + One2All 启动封装：

1. Profile 默认存放在用户本地的专属目录，例如 `~/.agent-browser/profiles/one2all`；目录权限限制为当前用户。
2. 启动封装固定使用该 Profile、可见模式和 One2All 精确域名白名单。
3. 首次访问若检测到登录页，暂停并提示用户在该可见窗口完成一次登录；不尝试代填凭据。
4. 登录完成后继续提单，后续启动直接复用已保存的浏览器会话。
5. 若 Profile 损坏或无法连接，报告明确的恢复动作，不自动删除或覆盖用户数据。

右侧 Codex 浏览器仍作为首选可见入口；当其会话不可接管或上传控件不可用时，才使用上述专属 Profile，避免再次启动无登录态的临时浏览器。

## 组件与数据流

- `tools/one2all_browser`：启动、域名限制、Profile 路径和登录检测。
- `codex-skills/skills/one2all/SKILL.md`：规定浏览器选择顺序和备用 Profile 的调用方式。
- `~/.agent-browser/profiles/one2all`：仅由浏览器进程维护的本地会话数据，不纳入 Git。
- `.gitignore`：忽略任何本地 Profile、缓存、下载和截图临时目录。

流程：`启动封装 -> 检查 One2All 页面 -> 已登录则继续 / 登录页则用户一次性登录 -> 提单 -> 保存详情和截图校验`。

## 错误处理

- 登录过期：保留当前页面，提示用户登录，不提交半成品 BUG。
- 浏览器唤醒失败：重试一次并保留诊断信息；不切换到无登录态临时 Profile。
- 上传失败：按 One2All 规则重试一次；仍失败则停止，不提交无截图 BUG。
- Profile 权限或路径异常：报告路径和修复建议，不删除现有 Profile。

## 验证与验收

1. 在干净调用中启动 One2All，确认使用专属 Profile。
2. 完成一次人工登录后关闭并重新唤醒，确认直接进入 One2All 而非登录页。
3. 访问其他域名，确认启动封装不会复用该 Profile。
4. 使用已登录会话完成一次带截图 BUG 提交，并回读详情页验证需求、环境、严重级别、优先级、步骤、实际/期望结果和材料数量。
5. 检查 Git 工作区不包含 Profile 或会话文件。

## 风险与取舍

专属 Profile 会在本机保存浏览器会话，因此必须限制目录权限并避免纳入版本库。相比导出 Cookie/Token 文件，该方案不增加新的凭据搬运链路；代价是首次需要用户在可见窗口完成一次登录。
