# One2All 快速提 BUG 与登录复用设计

## 背景

现有 One2All 提单流程优先使用 Codex 右侧浏览器。质量管理模块由 micro-app 承载，右侧浏览器能够读取和填写文本，但按钮点击在窄视口及弹窗场景下可能无法命中。失败后再切换浏览器、重复登录和重新定位表单，会显著拉长简单 BUG 的提交时间。

本次已验证的稳定链路是：使用 One2All 专属持久 Profile 完成一次飞书授权，直接进入新建质量问题地址，通过可见浏览器填写表单，提交后回读详情页确认保存结果。

## 目标

- One2All 提 BUG 默认复用已授权的专属浏览器 Profile。
- 避免右侧 micro-app 点击失败后才切换浏览器的重复尝试。
- 直接进入新建 BUG 页面，减少页面跳转和元素定位。
- 为“只要提成功”“随机提一个”等请求提供快速模式。
- 保留完整 QA 模式，用于需要查重、截图、严格需求匹配和完整证据链的缺陷。
- 无论采用哪种模式，都必须在保存后回读详情页，再报告成功。

## 非目标

- 不保存、导出或打印密码、Cookie、Token、授权码或浏览器存储内容。
- 不把专属 Profile、截图缓存或认证文件提交到 Git。
- 不取消严重级别、优先级和必填字段校验。
- 不把 One2All BUG 同步到禅道。
- 不为追求速度而伪造缺陷、影响范围、需求归属或保存结果。

## 方案选择

采用三层固化方案：

1. 工作区记忆：在根目录和 QA-agent 的 `AGENTS.md` 中加入 One2All 快速提单规则。
2. 技能流程：更新 `codex-skills/skills/one2all/SKILL.md`，明确快速模式、完整模式和浏览器选择顺序。
3. 快捷入口：增加一个薄封装脚本，统一启动专属 Profile、打开新建 BUG 页面并提供稳定的后续操作入口。

不实现完全无人值守的“任意文本自动提交器”。需求关联、严重级别和优先级仍需要基于已知事实确定，避免为了速度提交错误数据。

## 浏览器与登录策略

### 默认顺序

One2All 提 BUG 是右侧浏览器默认策略的特例：

1. 优先使用 `~/.agent-browser/profiles/one2all` 对应的可见专属会话。
2. 直接打开 `http://192.168.113.115:32633/one2all/workspace/quality-management/bugs/new`。
3. 如果已登录，立即进入填写流程。
4. 如果登录失效，保留当前可见窗口，仅提示用户完成一次登录或飞书授权。
5. 登录成功后继续当前表单，不关闭会话、不重建 Profile、不重复启动临时浏览器。

右侧 Codex 浏览器仍可用于用户明确要求在右侧观看、只读检查或页面验证，但不再作为 One2All 创建 BUG 的首选写入链路。

### 安全边界

- Profile 只允许访问 `192.168.113.115`。
- Profile 目录权限仅限当前用户。
- 不调用 Cookie、Storage、Token 导出命令。
- 飞书 OAuth 出现新增权限时，按授权确认规则处理。

## 两种提单模式

### 快速模式

触发条件包括：用户明确说“只要提成功”“随机提一个”“随便提一个”“不要复杂”“快速提交”，或用户已经给出完整缺陷内容且未要求完整测试证据。

流程：

1. 使用专属 Profile 直达新建 BUG 页面。
2. 使用用户提供的缺陷；若用户要求随机提交，只能从当前页面实际可验证的问题中选择，不得编造。
3. 快速检查是否存在明显同名或同现象记录；不进行大范围历史研究。
4. 选择唯一可信需求。若用户未提供范围，但缺陷属于 One2All 自身质量管理功能，可使用已验证的 `test > test > PMMCP` 作为平台自测需求；其他业务缺陷不得套用该映射。
5. 填写标题、需求、严重级别、优先级、发现环境、复现步骤、预期结果和实际结果。
6. 用户未要求截图且缺陷可由明确数值或文本证据复现时，可不上传材料。
7. 提交一次，回读列表行和详情页，确认编号、标题、需求、分级、环境及三段正文非空。
8. 返回 BUG 编号和详情链接。

### 完整模式

适用于正式验收、发布阻断、高风险缺陷、用户要求截图或完整证据、需求归属不明确、疑似重复缺陷等场景。

保留现有流程：复现、证据采集、查重、精确需求匹配、附件上传、字段复核、详情回读和材料预览验证。

## 字段和数据规则

- 标题只添加一个 `【Codex自动化】` 前缀。
- 未提供实际环境时，`发现环境` 使用 `test`。
- 严重级别和优先级继续独立判断，不照搬表单默认值。
- 用户明确要求快速提交，不代表允许虚构严重性、优先级或需求。
- 平台自身质量管理问题可使用 `test > test > PMMCP`；该映射必须限制在 One2All/PM 平台自身缺陷。
- 负责人和截止日期默认留空。
- 文本必须写入真实换行，不得把 `\n` 字面量保存到正文。

## 快捷脚本

在 One2All Skill 的 `scripts/` 目录增加薄封装，职责仅包括：

- 使用固定 session 和专属 Profile 启动可见浏览器；
- 限制允许访问的域名；
- 默认打开新建 BUG 页面；
- 提供 `open`、`snapshot`、`close` 等稳定入口；
- 避免在守护进程已运行时重复传入启动参数和输出无关警告；
- 保留原始 `agent-browser` 参数透传能力。

脚本不保存缺陷内容，不读取认证数据，也不自动猜测业务需求。

## 错误处理

- 登录页：停止填写，保留窗口，提示用户只完成一次登录。
- 表单加载超时：先读取当前 URL 和快照；确认页面仍在加载后只重试一次。
- 需求不唯一：快速模式暂停并给出候选，不选择列表第一项。
- 提交结果不确定：按标题和创建时间搜索，禁止直接再次点击提交。
- 详情缺字段：进入编辑页修复并重新回读；仍失败则明确报告未完成。
- 专属会话损坏：不自动删除 Profile，报告恢复动作并等待授权。

## 验证与验收

1. 关闭当前自动化连接后重新运行快捷入口，确认不要求重复飞书授权。
2. 从启动到出现新建 BUG 表单只经过一次直接导航。
3. 快速模式填写一条测试缺陷，确认没有重复浏览器切换。
4. 保存后回读详情，确认编号、需求、严重级别、优先级、环境、步骤、实际结果和预期结果。
5. 验证正文包含真实换行，不包含可见的 `\n` 字面量。
6. 验证 Profile、认证数据和本地缓存未进入 Git 状态。
7. 验证完整模式仍能执行查重、附件上传和材料预览检查。

## 成功标准

- 已登录情况下，简单 BUG 提交不再要求用户重复登录。
- 不再先尝试已知不稳定的右侧 micro-app 写入链路。
- 快速模式只执行必要操作，并始终返回已验证的 BUG 编号和详情链接。
- 完整模式的质量控制能力不降低。
