# One2All 自动关联需求规则设计

## 目标

One2All 提交 BUG 时默认自动匹配并关联正确需求，减少人工选择；同时禁止仅凭名称相似、表单默认值或单个关键词猜测需求。

## 方案

采用“唯一高置信匹配自动关联”方案。

匹配时综合使用以下证据：

- 用户明确提供的项目、项目集、需求名称或需求链接；
- 缺陷标题、受影响功能、最小复现步骤、实际结果和期望结果；
- One2All 当前项目范围及需求候选的项目、版本、模块和需求内容；
- 截图、日志、测试用例或需求文档中可以验证的归属信息。

只有候选需求同时满足项目范围一致、功能语义一致，并且不存在其他同等合理候选时，才允许自动关联。单纯包含“测试”“优化”“登录”等通用词不构成高置信证据。

## 决策规则

1. 用户明确指定唯一需求时，验证该需求与缺陷功能及项目范围一致后自动关联。
2. 未明确指定需求时，搜索 One2All 候选并进行证据匹配。
3. 只有一个高置信候选且明显优于其他候选时，自动选择该需求。
4. 出现多个相近候选、跨项目候选、候选内容不足或缺陷事实不足时，停止提交并让用户选择。
5. 没有可信候选时，不得使用第一项、最近使用项、表单默认项或名称最相似项代替。

## 提交与验证

- 选择后、提交前重新核对页面展示的项目集、项目和需求名称。
- 提交后重新读取缺陷详情，确认保存的需求与提交前选择一致。
- 如果保存结果为空或不一致，立即通过编辑流程修复并再次验证；修复失败时报告提交未完成，不得宣称成功。

## 验收场景

- 唯一且证据充分的候选：自动关联并成功提交。
- 两个需求名称相近且都可能匹配：停止并展示候选，等待用户选择。
- 候选属于错误项目或版本：排除，不得自动关联。
- 只有通用关键词匹配：视为证据不足，不得自动关联。
- 提交后需求字段丢失或变化：自动修复并复核，无法修复则报告失败。
