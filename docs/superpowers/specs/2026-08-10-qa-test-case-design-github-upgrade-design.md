# QA Test Case Design GitHub 增强升级设计

## 目标

在现有 `qa-test-case-design` Skill 基础上，吸收 GitHub 项目 `naodeng/awesome-qa-skills` 中 `testcase-writer-plus` 的有效能力，形成一个统一、无触发冲突、适合 QA 负责人使用的测试用例生成 Skill，并安装到 Codex 全局 Skill 目录。

## 当前基线

现有 Skill 已具备：

- 等价类、边界值、判定表、状态迁移、场景法等测试设计方法。
- 异常、并发、重复提交、超时、重试、回滚、权限绕过等专项覆盖。
- 用户偏好的飞书测试用例结构：文档标题、文档信息、测试用例汇总、按模块拆分的用例表。
- 稳定用例 ID、P0-P3 优先级、可执行步骤和可观察预期结果。

GitHub 增强版补充的主要能力包括：

- 需求、PRD、技术说明、历史缺陷和风险材料的多来源交叉分析。
- 需求或风险到测试用例的强制追踪关系。
- 基于业务影响与失败概率的风险优先级。
- 多来源冲突、假设和信息缺口的显式记录。
- 高风险路径的正向、异常、边界最低覆盖门槛。
- 冒烟子集、执行顺序、自动化候选和发布阻塞项建议。

## 方案

采用原地升级方案，继续使用 `qa-test-case-design` 名称，不并行安装 `testcase-writer-plus`，避免两个相似 Skill 同时触发。

规范源目录为：

`QA-agent/codex-skills/skills/qa-test-case-design`

同步镜像目录为：

`skills-bundles/qa-test-case-design`

最终安装目录为：

`~/.codex/skills/qa-test-case-design`

## Skill 结构

升级后保持渐进式加载：

- `SKILL.md`：触发条件、核心工作流、强制约束、资源路由和交付自检。
- `prompts/advanced-test-case-design.md`：多来源分析、风险策略、追踪矩阵、覆盖门槛和完整输出规则。
- `output-templates/feishu-test-cases.md`：用户偏好的飞书测试用例文档结构。
- `output-templates/structured-test-cases.md`：非飞书场景下的标准结构化用例模板。
- `references/case-writing-rules.md`：测试设计方法、优先级、可执行性和自动化候选规则。
- `scripts/validate_testcases.py`：对 Markdown 交付物执行轻量静态校验，检查必要章节、用例 ID、优先级和追踪矩阵引用一致性。
- `agents/openai.yaml`：更新展示名称、简介和默认调用提示。

## 工作流

1. 识别输入来源、范围、角色、状态、规则、数据和集成点。
2. 分离已确认事实、来源冲突、当前假设和信息缺口。
3. 按业务影响与失败概率形成 P0-P3 风险策略。
4. 使用适当测试设计方法生成测试用例；高风险路径默认覆盖正向、异常和边界。
5. 为每条用例绑定需求、故事或风险引用；无正式 ID 时生成稳定短标签。
6. 默认按用户的飞书文档样式分模块输出，不用一张超大表。
7. 生成追踪矩阵、冒烟子集、建议执行顺序和自动化候选。
8. 信息不足时仍输出可用初版，但不得编造字段、接口、错误码或环境细节。
9. 交付前运行结构检查，并对无法覆盖的检查项给出明确原因。

## 输出兼容性

- 保留现有列：`用例ID`、`用例名称`、`前置条件`、`测试步骤`、`预期结果`、`优先级`。
- `测试步骤`和`预期结果`继续在单元格内编号。
- 追踪引用、测试数据、类型和自动化候选优先放入模块前说明或用例补充信息；用户要求完整字段时才扩展表格，避免破坏默认飞书样式。
- 冒烟或轻量需求允许缩减输出，不强制生成完整报告式章节。

## 冲突处理

- 本地用户偏好高于上游通用模板。
- 上游增强逻辑作为能力来源，不直接覆盖本地 Skill。
- 当多个来源存在冲突时，不静默选择其一；记录冲突来源，并生成争议点保护用例或标记阻塞澄清。
- 当需求信息不足时，区分“可合理推断”和“必须待确认”，所有推断均显式标记。

## 安装与回滚

- 先在项目目录完成合并和验证，再安装到全局目录。
- 安装前检查全局目标；若已存在，则创建带时间标识的备份后再更新。
- 安装后重新读取全局 `SKILL.md` 并运行官方 `quick_validate.py`。
- 回滚时可用安装前备份恢复；项目内规范源始终保留完整版本。

## 验证

验证分三层：

1. 结构验证：Skill frontmatter、命名、引用文件和 `agents/openai.yaml` 合法。
2. 静态验证：用例文档必要章节、稳定 ID、P0-P3、追踪矩阵引用一致。
3. 示例验证：使用包含登录、验证码、角色权限和异常限制的混合需求，确认输出同时满足：
   - 飞书默认文档结构；
   - 多来源和假设说明；
   - 风险优先级；
   - 正向、异常和边界覆盖；
   - 需求/风险追踪矩阵；
   - 冒烟子集与自动化候选。

## 非目标

- 本次不配置或调用飞书 API。
- 本次不修改 OpenClaw Skills。
- 本次不并行安装名称相近的上游 Skill。
- 本次不扩展到测试计划、自动化脚本生成或缺陷提交工作流。
