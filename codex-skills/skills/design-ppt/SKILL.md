# design-ppt

做美观、能放映、不像模板填空的 PPT / slide deck。

载体默认是 HTML 单文件 slide deck(可直接预览、截图)。若用户明确要 `.pptx`,规则同样适用,只换实现方式。

## 按需加载

| 你要做的事 | 去看 |
|---|---|
| 套一个干净的页面骨架(日报/经营分析/财务/复盘/培训/发布) | [references/structure-templates.md](references/structure-templates.md) |
| 参照成品看质量水准(工艺/密度/克制度),**风格不照搬** | [example/example.html](example/example.html) |
| 逐页排版、自检、验收 | 本文件下面的硬规则 |

先看 `example/example.html` 的质量水准(信息密度、克制度、工艺)再开始。它是"美观到什么程度"的标尺,**不是模板**:配色、字体、整体风格按本任务的受众和调性自己定,别套它的样子,更别照抄内容。

## 工作流

1. **只定两件事**:画布(默认 16:9)和信息密度(汇报型留白 / 阅读型均衡 / 数据型密集)。其它能从内容推断就推断,不要拿问卷打断用户;真有影响结构的关键缺口,最多问一个。
2. **先定 deck token,再逐页做**(见下),一次定好全程不换。
3. 需要章节骨架时,从 `references/structure-templates.md` 取对应模板,按用户真实内容增删,不机械凑页。
4. 逐页按下面的硬规则排版。
5. 截图自检 → 修问题 → 复查受影响页。

## Deck Token(先定,后逐页做)

整套 deck 共用一套 token,不要边做边换风格:

- **字体层级**:封面标题、页标题、结论句、正文、注释、图例,字号各自固定。
- **颜色**:主文字、中性背景、1 个强调色、风险色、成功色、图表色,角色分清,不混用。
- **组件**:KPI、标签、表格、图例、箭头、时间线用同一套样式。
- **页脚**:页码、章节、日期、logo 位置固定,不逐页漂移。
- **网格**:统一页边距、安全区、标题区、内容区。

## Slide 硬规则(美观红线)

- 每页只讲一个观点;讲不清就拆页。
- 标题写结论,不写"背景介绍""数据分析"这类空标题。标题最好含对象+变化+判断,能单独读懂。
- 每页可见正文 ≤ 80 个中文字;高管简报压到 30-60 字。附录/明细页可破例,但要明确是查阅页。
- 项目符号每页 ≤ 5 条,每条 ≤ 18 字。
- 字号下限(16:9 放映):标题 ≥ 28pt,正文 ≥ 16pt,注释/来源 ≥ 9pt,图例/轴标签 ≥ 10pt。表格低于 10pt 不可读就拆页、删列或转附录。
- 页边距 ≥ 画布短边 5%;重要内容在安全区内,距边缘 ≥ 0.5 英寸。页码/logo/密标不侵入正文。
- 统一母版、网格、字体层级、颜色 token、组件样式,全程不重新选字体颜色圆角。
- 每页强调色只用 1 个,只用在真正要注意的地方。
- 连续 3 页以上同构页面必须换节奏:插入章节页、结论页、图表页或对比页。
- 封面/章节/结论页可以更强视觉;正文页以阅读效率优先。
- 正文左对齐;居中只用于封面、章节、结论或短句强调。

## 信息密度与垂直节奏(最容易翻车)

每页都要在画布里**密度均衡**,这是排版最常翻车的地方:

- 内容填满画布,但不是堆满:上下密度均衡,不能上半挤、下半留一大块空白。
- 节奏统一:eyebrow→标题、标题→正文的间距全 deck 固定一致,不要每页不同。
- 主体内容区在标题下方**居中或等高撑开**,消化剩余空间;条目少的页(几张卡、几行清单)让它们居中或等高分布,别堆在顶部、空在底部。
- 需要撑满高度时,让真正的视觉元素(图、卡、占位图)变大去填充,而不是把文字拉开、让分割线空一截。
- 绝对定位的页眉页脚要留出空间,正文不要压上去或被裁切。

## 图形优先于文字

**能用图形表达的就不要堆文字。** 每页先问:这页信息能不能可视化?

- 数据、对比、趋势、构成、占比 → 图表。
- 流程、步骤、因果、时间顺序 → 流程图、箭头、时间线。
- 结构、关系、层级 → 结构图、矩阵、分组。
- 单一关键结论 → 大数字 / 主视觉 + 一句话,而不是一整段。
- 状态、进度、健康度 → 仪表、进度环、状态徽章。
- 真实对象(产品、场景、人)→ 配图(占位图)。

文字的角色是**标题写结论 + 图形旁的精炼标注**,不是信息主体。
反面:一页纯文字段落、把可对比的数据写成句子、把流程写成一二三四行字。
即使是"结论页",一张能代表结论的图 + 一句解读,通常也比一句大字更直观。
但别为配图而配图:图必须承载这页的核心信息,凑一张无关装饰图同样是 AI 味。

## 渐变、暗色与质感:只守底线

- **暗色**:不用纯黑铺底,留 2-3 级 surface;强调色克制,避开霓虹紫蓝。
- **浅色**:不靠浅灰文字牺牲对比。

**克制的渐变(可以用):**
- 有方向、低透明:径向光/线性光透明度压在 ~20% 以内,营造光感和焦点,不是发光球。
- 同色系、低饱和:渐变两端取相近色相(如深蓝 → 青),不跨彩虹。
- 服务焦点:用在标题、关键数字、主视觉、图表面积上,强化层级。
- 一处一用:一页最多一两处渐变质感,不让每个元素都发光。

**滑向 AI 味的渐变(不要):**
- 紫蓝/粉紫满屏渐变背景,任何主题都长一样。
- 多个高饱和光晕、霓虹光环、无意义粒子叠在一起。
- 玻璃拟态 + 渐变 + 大圆角 + 重阴影全堆上。
- 渐变盖过文字可读性,或纯为"显高级"而没有焦点。

## 配图与背景(分两类,用错就 AI 味)

PPT 好看很大程度靠配图,但两类视觉资产要分开处理:

**位图 / 照片类**(产品图、场景、人物、案例截图、实拍)→ **用占位图,不要自己编造。**
- 这类图要靠生图模型或用户素材;skill 不能拿通用插画、emoji、在线随机图凑数。
- 做法:在正确位置放一个占位框,锁定比例和尺寸,框内标注「该放什么:具体内容 + 比例」,可附一句生图 prompt 供用户替换。
- 占位框风格统一(浅灰底 + 居中说明 + 1px 边界),当成最终图来留白和对齐,替换后即成型。
- 标注的是**具体内容**(如"北区门店实景"),不是"科技感氛围图";不为了"有图"塞无关照片或紫蓝渐变。

**矢量 / 程序化**(背景色块、克制渐变底、几何装饰、分隔形状、SVG 图标、SVG 图表)→ **自己用代码生成。**
- 这些 AI coding 能直接产出且可控,优先自己写。
- 背景服务调性、克制有据:品牌色块、低对比几何、单色底;不做满屏光晕、粒子、紫蓝渐变。
- 图标用统一一套 SVG,不混 emoji。

封面、章节页、产品/方案页配图需求高;数据页、附录页以图表表格为主,不硬塞配图。

## 图表与数据(看得见的可信)

- 先想清这张图要证明什么结论,再选图;图撑不起标题就换图或换标题。
- 图表类型按数据自己选;skill 只防滥用:占比类别超过 5 个不用饼图(改条形),不用 3D / 渐变 / 阴影图制造假精致,不把图表当装饰背景。
- 必须标单位、期间、口径、来源;同比/环比写清比较对象;峰值、低谷、超预算等关键点要标注。

## 反 AI 味(命中即重做)

- 三图标 + 三卡片 + 一句口号的万能页。
- 把紫蓝满屏渐变、多重霓虹光晕、无意义粒子当默认高级感(克制的单向渐变见上文,允许)。
- 空泛封面副标题:智启未来、数智赋能、共创辉煌、创新驱动。
- 每页标题都像作文题,而不是业务判断。
- 图表无单位、无口径、无标注,只为好看。
- 大段文字缩到 8-10pt 硬塞进一页。
- 用"感谢聆听"当结尾,而不是行动页/决策项/总结。
- 图标混用线性、填充、3D、emoji;图片低清、拉伸、纯氛围。
- 把用户原始材料整段搬上页,不提炼观点。

## 截图自检(交付前必做)

导出或截图后逐页查,目标是找问题不是确认自己对:

溢出 · 遮挡 · 低清 · 单位是否统一 · 页码是否正确 · 2-3 米外标题和关键数是否可读 · 对齐是否在同一网格 · 浅字弱线是否看不清 · 图表坐标/图例/来源是否完整 · 是否连续多页同构。

发现问题先修再复查。第一轮一个问题都没找到,就换更严格视角再查一遍。

## 验收

- 整套 deck 能用一句话说清主线;每页能用一句话说清观点,标题比正文更像结论。
- 关键数字有口径、单位、比较对象。
- 母版、token、字体、颜色、图表风格一致。
- 放映截图里没有溢出、遮挡、低清、页码错误、不可读小字。
- 最后一页服务目标:决策、行动、总结、试点或答疑,不是"谢谢"。
- 仍像模板填空,就继续重写标题、结构和页面节奏。
