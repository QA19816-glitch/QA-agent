# 测试用例设计与编写规则

## 设计方法选择

- 等价类：输入、角色、账户、文件类型、配置和状态可分组时使用。
- 边界值：数量、金额、长度、日期、超时、分页、上传限制和阈值规则使用。
- 判定表：多个条件共同决定结果、权限矩阵或优惠/资格组合使用。
- 状态迁移：订单、审批、支付、工单、库存、异步任务和生命周期使用。
- Pairwise：参数很多且组合爆炸时使用，同时保留关键业务全组合。
- 场景法：跨页面、跨服务、端到端主流程和异常恢复使用。
- 错误推测：结合历史缺陷、线上事故和系统薄弱点补充。

## 强用例标准

- 一个用例只验证一个清晰结果，避免失败后无法定位。
- 前置条件可复现，不依赖“系统已有数据”等隐式状态。
- 测试数据给出类别、边界或确定值，不只写“准备测试数据”。
- 步骤以动作开头并按顺序编号。
- 预期结果对应步骤，描述页面、接口、数据库、消息、日志或状态的可观察变化。
- 需要清理数据或恢复状态时，在备注中明确说明。

## 风险优先级

- P0：核心结果不可达、发布阻塞、资金/数据/安全风险或广泛不可用。
- P1：重要业务、高频路径、关键集成或历史高缺陷区域。
- P2：常规功能和有限影响异常。
- P3：低频边缘和轻微体验补充。

优先级由业务影响和失败概率共同决定，不按用例类型机械映射。

## 专项检查

按适用性检查：

- 权限绕过、横向/纵向越权、角色切换和会话失效。
- 重复提交、幂等、并发覆盖、锁冲突和最终一致性。
- 超时、重试、降级、回滚、补偿和依赖部分成功。
- 缓存、旧数据、过期数据、跨版本兼容和灰度差异。
- 空值、极值、非法字符、格式错误、超长内容和组合边界。

## 自动化候选

优先标记满足以下条件的用例：

- 高频冒烟或回归执行。
- 输入和前置数据可稳定准备。
- 页面选择器或接口契约稳定。
- 断言客观、可重复且清理成本可控。
- 手工执行耗时或容易遗漏。

探索性、强视觉判断、一次性变更和依赖不稳定环境的用例，不要为了自动化率强行标记。
